# Next.js 前端迁移设计

## 目标

把 `frontend/` 从 Expo/React Native 迁移为 Next.js 16 App Router，沿用参考前端的墨玉、鎏金、修仙视觉，但所有对局状态、合法动作与隐藏信息继续以 FastAPI 为唯一权威。前端部署到 Vercel，后端继续通过 Render Docker 运行。

## 架构与数据流

Next.js 只负责页面外壳、客户端状态和动画。API 客户端通过 `NEXT_PUBLIC_API_BASE_URL` 访问 `/api/v1`；创建游戏和提交动作后，Zustand 保存最新 `GameView`。按钮永远来自 `legal_actions`，不在浏览器复制规则。一次请求返回的事件先进入动画队列，按 `seq` 顺序展示；权威局面可以先更新，但输入保持锁定，直到玩家看完或主动跳过动画。

观星术和逆天改命进入 `REORDER_TOP` 后，立即打开不可自动消失的牌顶面板。面板直接读取 `observation.private_context.cards`，显示真实卡面、顺序编号和“下一张”标记，支持按钮与拖拽排序，确认后回传 token 顺序。普通已知牌顶读取 `observation.known_top`，仅本人可见。

## 交互与视觉

整体采用手机竖屏优先、桌面居中扩宽的响应式战场。正文不小于 12px，关键按钮和状态不小于 14px；中文不使用夸张字间距，所有文本容器允许换行并设置安全层级，避免文字被背景或固定操作栏遮挡。战斗事件默认每条停留 1.5–2.8 秒，重大事件更长；提供“慢速/标准/快速”和“跳过当前演出”，且遵守系统减少动态效果设置。

特效聚焦于事件语义：出牌飞入阵眼、天劫雷光、护劫金盾、观星星轨、洗牌涟漪和淘汰暗场。战斗日志永久保留，让任何闪过的事件都能复查。动画只解释事件，不参与规则判断。

## 错误处理与验证

网络失败、超时、409 revision 冲突和 Render 冷启动都显示明确状态；冲突后重新拉取最新局面。验证包括 TypeScript、ESLint、Next production build、后端 pytest、API E2E、所有特殊阶段交互、两种 AI 算法配置以及手机/桌面截图检查。
